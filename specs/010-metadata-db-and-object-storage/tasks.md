- [x] Initial migration: `upgrade()` creates every table with documented FKs/indexes, enables
      RLS (`ENABLE` + `FORCE ROW LEVEL SECURITY`) and adds the `USING (tenant_id =
      NULLIF(current_setting('app.current_tenant_id', true), '')::uuid)` policy on every
      table carrying `tenant_id` (including the newly denormalized columns); `downgrade()`
      drops policies, disables RLS, drops tables in dependency order — files:
      `packages/db/migrations/versions/0001_initial_schema.py` — hand-authored (not
      autogenerated) to mirror `models.py` exactly. **Verified: `alembic upgrade head` then
      `alembic downgrade base` then `upgrade head` again round-trips cleanly against a real
      local Postgres 16.** Two real bugs were found and fixed by this verification, not
      caught by unit tests alone — see plan.md's updated RLS bullet: (1) missing `FORCE ROW
      LEVEL SECURITY` meant the migration-running role, as table owner, bypassed RLS
      entirely; (2) the policy expression cast an empty-string GUC reset value straight to
      `::uuid`, which errors instead of denying cleanly under connection reuse — fixed with
      `NULLIF(..., '')`.
